# Navigate saved travel plans

Resolve the intended saved trip first. Use the departure date to distinguish trips
with matching names. Ask when the trip or day is ambiguous; never substitute a
different trip when a saved record has disappeared.

Use Open Trip Section for itinerary, today, map, checklist, collections, or saved
detail search. It opens the existing section in Trip. Open My Trips returns to
the trip library. Use read tools for spoken answers without navigating the app.

Use Open Trip Day Tool to review a day schedule, planning preview, weather, map,
or add places. Supply the person's day number, not a guessed date. These tools open the
existing workflow; they do not save a revised schedule or add a place themselves.
If schedule editing requires time-zone review, Trip opens that review first.

Use Edit Saved Trip Detail on the exact saved visit or booking when the person
wants its editor. Visit timing opens for a place; a booking opens its saved event
form. This does not contact a provider or change an actual reservation. Use Set
Visit Timing instead when the person explicitly requests a supported timing edit.

Use Open Trip Tool for trip details or a Calendar/Reminders export review. Export
review requires the person's selection and confirmation inside Trip; opening it
does not create Calendar events or Reminders. Respect unsupported-platform errors.

Use Create Trip only when asked to create a trip with a name, departure, and day
count. It creates a new saved trip. Use Start a New Trip for the creation form.
Do not repeat a completed creation. Existing unsaved edits block navigation;
explain the returned recovery instead of discarding drafts or claiming success.
